# 记录模块 UI 统一重设计

> 日期：2026-11-19。状态：已批准（2026-11-19，方案 A「统一骨架 + 模块主色」）。

## 1. 背景与目标

用户已认可咖啡页的「点单笺」视觉方向，并确认不同记录类型可以使用不同配色，但需要保持同属 LifeTrack 的产品一致性。

可验收目标：

- 咖啡记录编辑页完成 Compose 落地：全屏编辑、顶部实时摘要、品种多行展示、自定义品种、偏好分组、固定保存区。
- 其他记录模块先各自产出单文件、可点击的 HTML 高保真原型，用于确认配色与信息层级。
- 所有页面遵守统一的中性色、字阶、间距、圆角和功能色；模块色只改变识别色和模块内强调区域。
- 咖啡页通过 `assembleDebug`、`testDebugUnitTest`、`lintDebug`。
- 原型在 390×844、768 宽和 1440 宽下无横向溢出，支持浅色 / 深色切换。

## 2. 非目标

- 不修改 Room schema、备份格式、统计口径或业务字段。
- 不在本轮直接改饮水、茶、运动、排便、经期、亲密关系的 Compose 源码。
- 不新增依赖、不改导航底栏结构、不改应用锁与敏感模块安全策略。
- 不把月经红色用于错误、删除等系统语义；功能色仍由全局主题控制。

## 3. 方案对比

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| A 统一骨架 + 模块主色 + 模块内强强调 | 产品一致，模块辨识度高，可逐步落地 | 需要先约束哪些区域可使用模块色 | 采用 |
| B 每个模块完全独立设计 | 单页表现力最强 | 学习成本高，组件重复，质量不稳定 | 不采用 |
| C 只替换图标和强调色 | 改动小 | 不能解决长表单、层级与录入效率问题 | 不采用 |

## 4. 设计约束与接口

- 全局基础色、正文、边框、保存/错误/成功色保持一致。
- 模块色使用范围：首页识别元素，以及模块内页的顶部摘要、图标容器、选中态、图表和少量小标签。
- 月经使用低饱和砖玫瑰 / 灰粉 / 暖酒红；亲密关系使用梅紫，避免与月经混淆。
- 咖啡 Compose 保持 `CoffeeEditorDialog` 对外签名不变，导航调用无需改动。
- 原型为无外部依赖的单文件 HTML，不引用网络字体、图片或脚本。

## 5. 验收证据

- 咖啡：构建、单测、lint 输出；如有设备则补 390dp / 深色 / 200% 字体截图。
- 原型：每个文件附 390、768、1440 三档截图或等价布局检查，交互点击验证和浏览器控制台无错误。
