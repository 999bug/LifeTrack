# LifeTrack 界面重设计 · 方案 A「林间日志」

> 范围：四个页签（今天 / 历史 / 统计 / 设置）的整体视觉与信息架构重构。
> 风格基线：延续现有森林绿品牌色，不换色、不换气质，重做层级与节奏。
> 配套原型：`docs/ui-redesign-prototype.html`（单文件，浏览器直接打开，可点、可切深浅色、可切页面）。
> 状态：设计稿 v2（2026-11-11 确认：底导改名「历史」、停用模块不进首页、月历按天查看），**尚未改动任何 Compose 代码**。落地前需按第 6 节逐文件确认。

## 1. 设计目标与原则

### 1.1 从现有代码诊断出的四个问题

| # | 问题 | 证据 | 后果 |
| --- | --- | --- | --- |
| 1 | 主次不分 | `TodayScreen.kt:150-179` 五个模块各一个等宽 `OutlinedButton` | 高频的「打卡」和低频的「亲密关系」视觉权重相同 |
| 2 | 标题重复 | `TodayScreen.kt:84` 与 `:189` 都叫「今日记录」 | 同一屏两次同名标题，用户不知道哪个是区块 |
| 3 | 缺少一键主入口 | 首页只有按钮，没有「当前状态 + 操作」合一的组件 | 想确认今天记了几次，要滚到顶部大卡；想记录，要滚到按钮 |
| 4 | 视觉语言分裂 | `Theme.kt` 只覆盖配色，typography/shape 全用 M3 默认 | 统计页像仪表盘、首页像表单，两个页面不像一个产品 |

### 1.2 四条设计原则

1. **状态与操作同位**。计数不再单独放一张卡，而是写在可点击的模块卡里——看到即能改，不用先定位再操作。
2. **三档视觉重量**。重点（主色块/大数字）、次级（普通卡）、弱化（辅助文字/停用态），全站只用这三档，不再出现「每张卡一样重」。
3. **颜色只做识别，不做装饰**。模块识别色仅出现在图标底、色点、3dp 竖条三处，面积极小，不参与大面积填色。
4. **克制的动效**。只保留「按下缩放 0.982」「页面切换 220ms 淡入位移 6dp」两类，其余不做。

## 2. 设计基础

### 2.1 色彩

**主色与中性色**

| Token | 浅色 | 深色 | 用途 | 对比度（浅 / 深） |
| --- | --- | --- | --- | --- |
| `primary` | `#33604A` | `#A9D8B4` | 主按钮、选中态、高亮柱 | 7.3:1 / 9.8:1 |
| `onPrimary` | `#FFFFFF` | `#0E1510` | 主色上的文字 | — |
| `primarySoft` | `#DDEBE0` | `#24382B` | 选中 chip、结论卡底 | 容器 |
| `bg` | `#F6F7F3` | `#0F1410` | 页面底色 | — |
| `surface` | `#FDFDFB` | `#171E19` | 卡片 | — |
| `surface2` | `#EFF2EB` | `#121814` | 分段控件槽、按下态 | — |
| `border` | `#E3E8DE` | `#2A342C` | 1px 描边、分隔线 | — |
| `text` | `#171A16` | `#E9F0E9` | 标题、正文 | 15.8:1 / 14.2:1 |
| `text2` | `#59625A` | `#A8B4AA` | 次级文字 | 5.9:1 / 7.9:1 |
| `text3` | `#69716A` | `#8B988E` | 辅助信息（时间、次数） | 4.7:1 / 5.5:1 |

> `text3` 是这次唯一的「必须变深」项。原设计的浅灰在浅底上只有 3.0:1，11.5sp 的小字用它不达 AA。宁可牺牲一点层次，也不留不达标文字。

**模块识别色**（只用于图标底 13% 透明度、色点、3dp 竖条）

| 模块 | 浅色 | 深色 | 作文字色时的对比度（浅/深） |
| --- | --- | --- | --- |
| 排便 | `#8A6A4B` | `#C9A382` | 6.0:1 / 7.4:1 |
| 饮水 | `#3D7391` | `#8FC0D8` | 6.2:1 / 8.7:1 |
| 咖啡 / 茶 | `#9A7134` | `#D9B173` | 5.4:1 / 8.5:1 |
| 运动 | `#4C7A57` | `#9CC7A6` | 6.0:1 / 9.1:1 |
| 亲密关系 | `#8A5F72` | `#C99BAE` | 6.4:1 / 7.2:1 |

全部 ≥ 4.5:1，可直接用作同色系文字（例如色点旁的标签），不必另配深色。

### 2.2 字阶

| 名称 | 字号 / 行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| Display | 44 / 44 | 620 | 统计页总量数字，等宽数字 |
| H1 | 27 / 32 | 640 | 页面标题（今天 / 历史 / 统计 / 设置） |
| H2 | 18 / 26 | 640 | 弹层标题 |
| Title | 15 / 22 | 620 | 区块标题（今日记录） |
| Subtitle | 14 / 20 | 600 | 模块名、设置项标题 |
| Body | 13 / 20 | 400 | 正文、摘要 |
| Label | 12 / 18 | 500 | 辅助信息、时间、次数 |
| Eyebrow | 12 / 16 | 500，字距 +0.04em | 标题上方的日期 / 范围 |

规则：

- 所有数字用等宽数字（Compose：`FontFeatureSetting("tnum")`），避免计数跳动时宽度抖动。
- 中文字号不小于 12sp；11.5 只用于非关键状态文字，且必须在 200% 字体下复核。
- 不使用 Material 3 默认 typography——它的 `headlineMedium` 在中文下偏松，标题改用 640 字重 + 负字距补偿。

### 2.3 间距与圆角

| 项 | 值 | 说明 |
| --- | --- | --- |
| 基准单位 | 4dp | 所有间距为其倍数 |
| 页面水平内边距 | 20dp | 首页 / 历史 / 统计 / 设置统一 |
| 卡片内边距 | 16dp（模块卡 13dp） | 小卡用小值，避免视觉过重 |
| 卡片间距 | 10dp | 网格 gap；列表区块之间 22dp |
| 圆角 | 卡片 16 / 按钮 12 / 胶囊 999 / 弹层 24 | 全站只有这四个值 |
| 描边 | 1dp `border` | 用描边代替阴影表达卡片边界 |

**层级表达**：不堆阴影。卡片 = `surface` + 1dp 描边 + 极轻阴影（`0 1px 2px rgba(23,26,22,.04)`）。强调块 = `primarySoft` 底 + 3dp 左侧主色条。

### 2.4 动效

| 场景 | 时长 | 曲线 |
| --- | --- | --- |
| 按下反馈 | 120ms | 缩放到 0.982 |
| 页面切换 | 220ms | 淡入 + 上移 6dp |
| 柱状图变化 | 320ms | `cubic-bezier(.2,.7,.3,1)` |
| 弹层 | 260ms | 自底部滑入 |

`prefers-reduced-motion` / 系统「移除动画」开启时，全部降为瞬时切换。

## 3. 组件规格

### 3.1 模块卡（ModuleCard）

首页核心组件，替代原来的按钮列表。

| 属性 | 规格 |
| --- | --- |
| 尺寸 | 双列网格，单卡最小高 104dp；落单时横向撑满（最小高 48dp） |
| 结构 | 3dp 左侧色条 · 30dp 图标（圆角 9，底色为模块色 13%）· 名称 · 状态行 · 右上 + 圆钮 · 右下「详细」 |
| 主操作 | 有合理默认值的模块（排便、饮水）整卡点击 = 立即记录；无默认值的（咖啡、运动）整卡点击 = 打开编辑器 |
| 次操作 | 「详细」始终打开完整编辑器 |
| 停用态 | 卡片降为 62% 不透明，状态行写「已停用 · 在设置中启用」，点击弹出说明并提供「去设置」 |
| 无障碍 | `contentDescription` = 名称 + 今日次数 + 主操作结果，例如「饮水，今日 3 次共 750 毫升，点按记录一杯 250 毫升」；触摸目标 ≥ 104×160dp |

### 3.2 时间轴（TimelineItem）

| 属性 | 规格 |
| --- | --- |
| 行高 | 内容自适应，单行约 54dp，双行约 62dp |
| 三列 | 时间 46dp（右对齐）· 轴线区 14dp · 内容区 |
| 轴线 | 1.5dp `border`，从色点下方 4dp 延伸到下一行起点；最后一条不画 |
| 色点 | 9dp 实心模块色，外圈 3.5dp 页面底描边，压住轴线 |
| 点击 | 整行打开只读详情弹层（沿用现有 `RecordDetailSheet`） |

### 3.3 分段控件（SegmentedControl）

| 属性 | 规格 |
| --- | --- |
| 容器 | `surface2` 底 + 1dp 描边，圆角 999，内边距 3dp |
| 选项 | 高 34dp，选中 = `primary` 实底 + `onPrimary` 文字 600 字重 |
| 无障碍 | 每项 `selectable(role = Role.Tab)`，保留现有 B3 的语义改造 |

> 现有实现在 200% 字体下用固定高度会把文字压扁（项目雷区已记录）。这次高度改为 `heightIn(min = 34.dp)`，并随 `fontScale > 1.3` 抬到 48dp。

### 3.4 指标卡 / 结论卡

- 指标卡：2×2 网格，`surface` + 描边，标签 11.5sp `text3`，数值 18sp 620 字重。
- 结论卡：`primarySoft` 底 + 3dp 左主色条，两行文字（第一行 12.5sp 主色深，第二行同色 78% 不透明）。

### 3.5 设置行（SettingsRow）

| 属性 | 规格 |
| --- | --- |
| 行高 | 最小 54dp，两行文字时自适应 |
| 结构 | 20dp 图标（`text3`）· 标题 14sp / 描述 11.5sp · 行尾值或 chevron |
| 分隔线 | 从文字起始处缩进，颜色为 `border` 65% |
| 分组 | 组标题 11.5sp 600 字重、字距 +0.05em，段间距 22dp |

### 3.6 月历格（CalendarDayCell）

| 属性 | 规格 |
| --- | --- |
| 尺寸 | 7 列等分，宽高比 1 : 1.38（412dp 宽屏下约 47×65dp，触摸目标达标） |
| 内容 | 上：日期 12sp；下：类型图标行，间距 5dp |
| 类型图标 | 11dp 实心 path，去重后最多 3 个，颜色取模块识别色 |
| 今天 | 背景 `primary` 实底，日期与图标转 `onPrimary` |
| 选中 | 1dp `primary` 描边 + `surface2` 底，弹层关闭后清除 |
| 无记录 | 只显示日期，图标行保留 12dp 占位以保证全月等高 |
| 无障碍 | `contentDescription` = 「11月11日，周三，5 次，含饮水、咖啡、排便」 |

### 3.7 日期详情弹层（DayRecordsSheet）

| 属性 | 规格 |
| --- | --- |
| 触发 | 点击任意日期格（含无记录日） |
| 高度 | 内容自适应，最高 78% 屏高，内部滚动 |
| 头部 | 左「11月11日 · 周三」18sp 640；右「5 次」12sp `text3` |
| 列表 | 复用历史页行组件：时间 46dp + 色点 + 类型 + 摘要 |
| 空态 | 「这天没有记录。可在新增记录时把时间改到这一天。」 |
| 关闭 | 遮罩点击、关闭按钮；两者都清除日期格选中态 |
| 层级 | 与记录编辑器弹层同层，互斥，不同时出现 |

## 4. 四个页面的信息架构

### 4.1 今天

```
Eyebrow  2026年11月11日 · 周三
H1       今天
Sub      已记录 5 次 · 最近一次 12:30
────────────────────────────
模块网格（按用户排序，双列）
  排便   今日 1 次
  饮水   今日 3 次 · 750 ml
  咖啡   今日 1 次 · 250 ml
  运动   今日 0 次
────────────────────────────
今日记录                        查看历史
时间轴 07:12 → 12:30
```

改动要点：

- 删除原来顶部的「今日记录」大计数卡——它的信息被模块卡状态行与页头 Sub 完全覆盖，属于重复。
- 删除「快速打卡会立即保存当前时间……」这段说明文字。规则内化到组件行为里，不再用文案解释按钮。
- 排序仍按「记录项目」页的 `sortOrder`，不改变数据层。
- **停用的模块不进入首页**（2026-11-11 确认）。首页只渲染 `enabled = true` 的模块，不做灰显占位；启用入口只保留在「设置 → 记录项目」。原型中亲密关系已停用，首页为 4 张卡，2×2 正好对齐。

### 4.2 历史

- 顶部：Eyebrow「全部记录」/ H1「历史」/ Sub「本月 37 次 · 已连续记录 3 天」。
- 分段：列表 / 月历（同一份数据的两种密度，不是两个页面）。
- 列表：按天分组，日期头左「11月11日 · 周三」右「5 次」；行内时间 + 类型 + 摘要，无卡片边框。
- 筛选 chips 固定在列表顶部。

**月历格子**

- 7 列，格内上排日期、下排**微型类型图标**（11dp 实心），去重后最多 3 个：出现过哪几类就显示哪几个，重复类型不重复画。
- 今天为 `primary` 实心底 + 反白日期与图标。
- 底部图例对应四种类型，右端固定提示「点按日期看当天」。

> 为什么用图标而不是色点：色点只能回答「有几种」，图标能回答「记了什么」。11dp 是实心图形在 360dp 窄屏下的可辨识下限；再小就退化成色点，再大则一行放不下 3 个。

**日期详情弹层**

- 点任意日期，自底部弹出当天记录：标题「11月11日 · 周三」、右上当天总次数、下方逐条列出「时间 + 类型 + 摘要」。
- 无记录日期：不弹空白层，给一句「这天没有记录。可在新增记录时把时间改到这一天。」
- 关闭方式：遮罩点击、关闭按钮；被点中的日期格保留 `is-selected` 描边，直到弹层关闭。
- 弹层内容只读。要编辑，走列表页的记录详情——避免二级弹层套娃。

> 命名变更：底部导航「记录」→「历史」，2026-11-11 已确认。理由：与「今天」并列时，「记录」既可理解为动作也可理解为页面，而该页实际是全部记录的只读回看。

### 4.3 统计

保持现有结构（用户已认可仪表盘形态），只做 token 对齐与顺序强化：

```
Eyebrow  2026年11月9日 – 11月15日
H1       统计
分段     周 / 月 / 年
Chips    全部 / 饮水 / 咖啡 / 排便 / 运动
大数字   12 次   + 与上周对比
柱图     每日次数（今天高亮）
四宫格   日均 / 单日最高 / 最长连续 / 常见时段
结论句   本周共 12 次，比上周多 3 次。
辅助     本周记录集中在 07:00–09:00。
脚注     统计仅基于已保存的记录，不构成医疗诊断。
```

关键约束：**类型筛选必须联动全部数字**（总量、日均、最高、连续、时段、柱图、结论）。现有原型里各类型的数据是配平的：全部 12 = 饮水 7 + 咖啡 3 + 排便 2，柱图按日拆分后仍然对得上。

### 4.4 设置

分组从四段改为五段：**记录 / 数据 / 安全 / 外观 / 关于**。

- 「安全」从「数据」中独立。找应用锁的用户不会先去「数据」里翻。
- 「外观」为主体三分段（浅色 / 深色 / 跟随系统），切换即时生效，不需要重启。持久化新增 `theme_mode`，同时同步旧的 `dark_theme` 布尔键，回退到 0.6.x 时深色偏好不丢。
- 设置行左侧加 20dp 图标；分组标题改 11.5sp / 600 字重 / +0.6sp 字距，不与正文抢层级；卡片圆角统一 16dp。
- 状态用文字直说（「已开启」「已关闭」），不靠颜色单独表意。

> 实现状态（2026-11-11）：以上三项均已落地，见提交 `docs/PROGRESS.md` 台账「设置页主题三档」行。

## 5. 原型与 data 自洽说明

原型里的 mock 数据是逐项配平的，切换任何面板都不会出现自相矛盾：

| 面板 | 数据 |
| --- | --- |
| 首页 | 今日 5 次 = 排便 1 + 饮水 3 + 咖啡 1；时间轴 5 条；最近一次 12:30 |
| 历史 | 11/11 五条、11/10 四条、11/9 三条 |
| 统计（全部） | 本周 12 次 = 3 + 4 + 5；日均 1.7 = 12 ÷ 7；单日最高 5；连续 3 天 |
| 统计（分类型） | 饮水 7（2+2+3）、咖啡 3（1+1+1）、排便 2（0+1+1），三者相加 = 12 |
| 月历 | 11/9 = 3、11/10 = 4、11/11 = 5，与历史列表逐日一致 |
| 月历图标 | 每天出现过的类型去重后最多画 3 个（如 11/6 只有 1 条 → 1 个图标；11/4 有 5 条但只有 3 类 → 3 个图标） |
| 日期弹层 | 点 11 日列出 5 条，与历史列表 11/11 分组逐条相同；点 12 日（无记录）走空态 |

原型可交互项：四页切换、深/浅色切换（含设置页内三分段）、模块卡 +1 与计数联动、记录弹层、统计类型筛选、列表/月历切换、**月历点按日期查看当天记录**。

已验证：Edge 无头浏览器 1440×1100 下四页 + 深色 + 月历 + 日详情弹层 + 空态弹层截图；`--dump-dom` 确认脚本执行后柱图渲染 7 根、说明条目 5 条、`+1` 后页头由 5 次变为 7 次。

## 8. 已确认决策与已知风险

**已确认（2026-11-11）**

| 决策 | 结论 |
| --- | --- |
| 底部导航「记录」→「历史」 | ✅ 采纳。Compose 落地时改 `LifeTrackApp.kt` 的标签与 `README` 中的界面描述 |
| 停用模块是否留在首页 | ✅ 不显示。首页只渲染启用模块，不做灰显占位，启用入口只在设置页 |
| 月历显示粒度 | ✅ 从色点升级为类型图标，并支持点按查看当天明细 |

**仍待观察**

1. **模块识别色是否可关闭**：偏好极简的用户可能希望全灰。建议 v1 不做开关，先观察反馈。
2. **首页模块数为奇数时末位落单**：4 或 6 个模块时 2×2 / 2×3 自然对齐；5 个时会有一张横跨整行的宽卡（原型早期的亲密关系卡即为此形态，规则已实现，当前 4 个模块未触发）。不是布局 bug。
3. **月历图标在 360dp 窄屏下的密度**：格宽约 42dp，3 个 11dp 图标 + 4dp 间距 = 37dp，仍放得下；若实测挤，降为最多 2 个，第三个用「+」概括。
4. **两级弹层的关系**：日期详情弹层只读，点击其中一条不做任何跳转（避免弹层套弹层）。如果后续需要在弹层内直接编辑，改为「关闭日期弹层 → 打开记录详情」的替换式跳转，不做叠加。
5. **统计页「常见时段」的 16sp 字号**是为容纳 `07:00–09:00` 而单独下调，与其他三个指标不一致。若要严格统一，需把时间格式改为 `07–09 时`。
